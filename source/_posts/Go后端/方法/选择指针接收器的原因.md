#### 使用指针接收器有两个原因。

第一个原因是该方法可以修改其接收器指向的值。
指针接收器可以直接修改原始数据，值接收器只能修改副本。这是最直观的需求，比如下方实例中 `Scale` 方法要改变 `Vertex` 的坐标。

第二个原因是避免每次方法调用时都复制值。例如，如果接收者是一个大型结构体，这样做会更高效。
1.值接收器每次调用都会复制整个接收者。如果结构体很大，复制成本高，影响性能。
2.指针接收器只传递一个地址（8 字节），更高效。
3.即使方法只是读取数据（如下方实例中的 `Abs`），如果结构体字段很多，也可以用指针接收器来避免不必要的复制。

#### A Tour Of Go中的实例
此例源自A Tour Of Go——方法和接口——8/26——选择值或指针接收器
在这个例子中， `Scale` 和 `Abs` 都是接收器类型为 `*Vertex` 方法，即使 `Abs` 方法不需要修改其接收器：
```go
package main

import (
	"fmt"
	"math"
)

type Vertex struct {
	X, Y float64
}

func (v *Vertex) Scale(f float64) {
	v.X = v.X * f
	v.Y = v.Y * f
}

func (v *Vertex) Abs() float64 {
	return math.Sqrt(v.X*v.X + v.Y*v.Y)
}

func main() {
	v := &Vertex{3, 4}
	fmt.Printf("Before scaling: %+v, Abs: %v\n", v, v.Abs())
	v.Scale(5)
	fmt.Printf("After scaling: %+v, Abs: %v\n", v, v.Abs())
}
```

一般来说，给定类型的所有方法都应该有值接收器或指针接收器，但不能两者兼有。
原因：
1.混合使用会让该类型的方法集在不同场景下行为不一致，导致困惑。
2.某些接口的实现依赖于方法集，混合可能使类型无法满足接口。
3.统一风格让代码更可预测。
