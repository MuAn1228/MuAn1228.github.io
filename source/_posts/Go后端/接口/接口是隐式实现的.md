#### 定义
1.类型通过实现接口的方法来实现该接口。没有显式的意图声明，也没有“implements”关键字。
2.隐式接口将接口的定义与其实现解耦，这样一来，接口的实现就可以出现在任何包中而无需预先安排。

---

**隐式实现**是Go 接口的一个**核心设计**
#### 隐式接口的好处：解耦
定义中强调：
“隐式接口将接口的定义与其实现解耦，这样一来，接口的实现就可以出现在任何包中而无需预先安排。”

这意味着：
1.定义接口的包（比如标准库）和实现该接口的类型（比如你自己写的代码）可以**完全独立**。你不需要导入接口所在的包，也不需要声明“我实现了某某接口”。只要你的类型有这个接口要求的方法，它就自动满足了该接口。
2.这使你可以在后期方便地提取公共行为，或让已有的类型适配新的接口，而不必修改原有类型的定义。

例如，标准库的 `fmt.Stringer` 接口：
```go
type Stringer interface {
    String() string
}
```

任何类型只要定义了 `String() string` 方法，就能被 `fmt.Println` 等函数以自定义格式输出。你自己写的类型只要加一个 `String()` 方法，无需任何 `implements` 声明，就可以直接和 `fmt` 包配合。

#### 与显式接口的对比（如 Java）
在 Java 中，你必须显式地写 `class T implements I`，然后实现方法。类型和接口的绑定是紧耦合的，而且需要提前声明。Go 的隐式方式则让你事后也能轻松满足接口，更加灵活。

#### A Tour Of Go中的实例
此例源自A Tour Of Go——方法和接口——10/26——接口是隐式实现的
下面的示例代码中定义了一个接口 `I`，它只有一个方法签名 `M()`。
定义了一个包含一个字符串字段 `S`的结构体 `T`。
给 `T` 添加了一个方法 `M()`，打印 `t.S`。
在 `main` 中，创建了一个 `T` 类型的值 `T{"hello"}`，并赋值给接口变量 `i`（类型 `I`）。然后调用 `i.M()`，输出 `hello`。

关键点：**没有任何地方写 `T` 实现了 `I`**，也没有 `implements` 关键字。编译器根据 `T` 拥有 `M() 方法`，自动推断 `T` 满足 `I` 接口。

---

示例如下：
```go
package main

import "fmt"

type I interface {
	M()
}

type T struct {
	S string
}

// This method means type T implements the interface I,
// but we don't need to explicitly declare that it does so.
func (t T) M() {
	fmt.Println(t.S)
}

func main() {
	var i I = T{"hello"}
	i.M()
}
```
