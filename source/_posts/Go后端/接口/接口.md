#### 定义
**接口类型**定义为一组方法签名。
接口类型的值可以包含任何实现了这些方法的值。

简单来说接口就是一组方法的集合，类型只要实现了这些方法，就自动满足该接口，可以被赋值给接口类型的变量。

---

#### 那接口到底有什么用？为什么需要它？

接口最大的价值在于 **让不同类型的值能通过同样的方式被操作**，也就是 **多态** 和 **解耦**。
我们用比喻来理解：

**比喻：电源插座**
插座就是一个“接口”，它只规定了 **形状和方法**：两个孔，能插进去并且通电。
家里的台灯、电脑、充电器都 **实现了这个接口**（它们都有匹配的插头，且能用电）。
插座不关心插上来的是什么电器，只要它满足插头规格，就能工作。
你可以随时换一个电器，插座不用任何修改。

#### A Tour Of Go中的实例
此例源自A Tour Of Go——方法和接口——9/26——接口
例如在下面的示例中Abser这个接口里都是Abs()方法，有的Abs()是用于求一个数的绝对值，有的Abs()是求点到原点距离，变量a是Abser类型；MyFloat类型实现了Abs（）这个方法，所以MyFloat类型的f也是Abser类型；\*Vertex类型也实现了Abs（）这个方法，所以\*Vertex类型的&v也是Abser类型；Vertex类型没有实现了Abs（）这个方法，所以Vertex类型的v不是Abser类型，a=v错误

`MyFloat` 实现了 `Abs()`，所以 `f` 是 `Abser`
`*Vertex` 实现了 `Abs()`，所以 `&v` 是 `Abser`
`Vertex` 没实现 `Abs()`，所以 `v` 不是 `Abser`

在 Go 中，`Abser` 就像插座，`MyFloat`、`*Vertex` 就像不同的电器，它们都实现了 `Abs()` 方法。  
只要某个东西是 `Abser`，你就可以 **调用 `Abs()`，而不必关心它到底是什么类型**。

---

示例如下：
```go
package main

import (
	"fmt"
	"math"
)

type Abser interface {
	Abs() float64
}

func main() {
	var a Abser
	f := MyFloat(-math.Sqrt2)
	v := Vertex{3, 4}

	a = f  // a MyFloat implements Abser
	a = &v // a *Vertex implements Abser

	// In the following line, v is a Vertex (not *Vertex)
	// and does NOT implement Abser.
	a = v

	fmt.Println(a.Abs())
}

type MyFloat float64

func (f MyFloat) Abs() float64 {
	if f < 0 {
		return float64(-f)
	}
	return float64(f)
}

type Vertex struct {
	X, Y float64
}

func (v *Vertex) Abs() float64 {
	return math.Sqrt(v.X*v.X + v.Y*v.Y)
}
```
**注意：** 示例代码第 22 行有错误。 `Vertex` （值类型）没有实现 `Abser` ，因为 `Abs` 方法仅在 `*Vertex` （指针类型）上定义。

#### 进一步地：
**接口的实际威力：编写通用函数**

假设你想写一个函数，用来打印任何“能取绝对值的东西”的绝对值：
```go
func PrintAbs(a Abser) {
	fmt.Println(a.Abs())
}
```
这个函数可以接收 `MyFloat`、`*Vertex`，以及将来任何实现了 `Abs()` 的新类型。  
它**不依赖具体类型**，只要你有 `Abs()`，就能用。这就是解耦和可扩展性。

对比如果没有接口，你必须为每种类型写一个专门的打印函数，代码会膨胀且难以维护。

---

**接口作为合约**

接口定义了“行为合约”。  
例如 `fmt` 包里的 `Stringer` 接口：
```go
type Stringer interface {
    String() string
}
```
任何类型只要实现了 `String()` 方法，就可以被 `fmt.Println` 等函数以自定义格式打印。  
这种设计让你可以为自己的类型定制输出，而标准库完全不需要知道你的类型存在。
