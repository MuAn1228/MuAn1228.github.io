#### 定义
Go 程序使用 `error` 值来表达错误状态。
`error` 类型是一个内置接口，类似于 `fmt.Stringer` ：
```go
type error interface {
    Error() string
}
```
（与 `fmt.Stringer` 类似， `fmt` 包会在需要时查找 `error` 接口） 打印值。）
函数通常会返回一个 `error` 值，调用代码应该通过测试错误是否等于 `nil` 来处理错误。

```go
i, err := strconv.Atoi("42")
if err != nil {
    fmt.Printf("couldn't convert number: %v\n", err)
    return
}
fmt.Println("Converted integer:", i)
```

零 `error` 表示成功；非零 `error` 表示失败。

即如果一切正常，`err` 是 `nil`（表示没有错误）。
如果出问题了，`err` 不等于 `nil`，调用者应该检查并处理。
这种**显式检查 `err != nil`** 的方式是 Go 的错误处理惯例，让错误路径一目了然。

#### A Tour Of Go中的实例
此例源自A Tour Of Go——方法和接口——19/26——error

**示例代码详解**
###### 自定义错误类型
```go
type MyError struct {
    When time.Time
    What string
}
func (e *MyError) Error() string {
    return fmt.Sprintf("at %v, %s", e.When, e.What)
}
```

`MyError` 是一个结构体，包含错误发生的时间 `When` 和错误描述 `What`。
它实现了 `Error() string` 方法，因此 `*MyError` 实现了 `error` 接口。
`Error()` 方法格式化输出错误信息，例如：`"at 2009-11-10 23:00:00, it didn't work"`。
###### 产生错误的函数
```go
func run() error {
    return &MyError{
        time.Now(),
        "it didn't work",
    }
}
```

`run()` 返回一个 `error` 接口类型的值。
它返回一个 `*MyError` 指针（因为 `*MyError` 实现了 `error`），包含当前时间和错误消息。
注意：`run` 的返回值类型是 `error` 接口，但实际返回的是具体类型 `*MyError`，这是接口的典型用法（返回接口，隐藏具体实现）。
###### 调用并处理错误
```go
func main() {
    if err := run(); err != nil {
        fmt.Println(err)
    }
}

```
`err := run()` 调用了 `run`，得到一个 `error` 接口值。
`err != nil` 检查是否有错误（`*MyError` 值不是 `nil`，所以判断为有错）。
如果出错，用 `fmt.Println(err)` 打印错误信息。
**关键点**：`fmt.Println` 在打印 `error` 接口值时，会自动调用它的 `Error()` 方法，生成可读的字符串。这和 `Stringer` 接口的待遇完全一样。

#####  为什么平时写的函数只返回一个值，没有 `error`？
因为学go基础语法时写的函数大多是**肯定不会出错**的简单逻辑，比如计算平方根、打印、求和。这些操作不会遇到“文件不存在”“网络中断”“格式不对”等异常情况。

但在实际工程中，**很多操作是会失败的**：读文件可能文件不存在，字符串转数字可能格式不对，网络连接可能超时。  
Go 的惯例是：**只要函数可能失败，就把 `error` 作为最后一个返回值**，让调用者明确处理错误。  
所以你会看到：
```go
i, err := strconv.Atoi("42")   // 可能失败
f, err := os.Open("file.txt")   // 可能失败
```
而 `main` 函数一般只作为入口，可以直接打印错误并退出，不需要再向上返回，所以很多示例中的 `main` 不返回 `error`（实际上 `main` 函数签名没有返回值）。
