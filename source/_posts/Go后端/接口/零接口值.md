#### 定义
1.nil 接口值既不包含值，也不包含具体类型。
2.对 nil 接口调用方法是运行时错误，因为接口元组内没有类型来指示要调用哪个具体方法。

---

**nil 接口值**（真正的空接口）和之前的**接口内部值为 nil 但接口本身非 nill**有显著区别

---

#### A Tour Of Go中的实例
此例源自A Tour Of Go——方法和接口——13/26——零接口值
##### 1. 什么是 nil 接口值？
```go
var i I
```
只声明了接口变量 `i`，没有给它赋值。
此时 `i` 的**接口值**就是 `nil`，具体来说：它的**类型**是 `nil`，**值**也是 `nil`。
它就是一个真正的“空盒子”，里面没有东西，连标签（类型）都没有。

---
##### 2. 为什么调用 `i.M()` 会崩溃？
```go
i.M()   // panic: runtime error: invalid memory address or nil pointer dereference
```
接口值的底层结构是 `(类型, 值)`。
要调用一个方法，Go 必须根据**类型**去找到具体的方法实现。
nil 接口值连类型信息都没有，Go 不知道应该调用哪个类型的 `M` 方法，因此**必然引发运行时 panic**。

---
##### 3. 和之前学过的“接口内部值为 nil”的区别
我们在接口值，底层值为 nil节学了：
```go
var t *T        // t 是 nil 指针
i = t           // i 不是 nil！它持有 (*main.T, nil)
i.M()           // 安全，因为类型信息存在，会调用 (*T).M，且 M 内部处理了 nil 接收者 
```
这种情况接口变量 `i` **不是 nil**，它的接口值是 `(*T, nil)`——**有类型，无值**。方法可以正常调用。
而本节代码 `var i I` 从未赋值，接口值是 `(nil, nil)`——**无类型，无值**。调用方法直接 panic。

---
##### 4. `describe` 函数的输出
```go
func describe(i I) {
    fmt.Printf("(%v, %T)\n", i, i)
}
```
对于 nil 接口值，输出：`(<nil>, <nil>)`，表示值和类型都是空的。
对于“内部值为 nil”的接口，输出：`(<nil>, *main.T)`，类型还在。

---

#### 总结：
一个从未被赋值的接口变量就是 nil 接口值，它既没有类型也没有值。对它调用方法会直接崩溃，因为编译器不知道应该执行哪个具体类型的代码。这和“内部值为 nil 但类型还在”的情况完全不同。
