#### 定义
1.从本质上讲，接口值可以被视为一个包含值和具体类型的元组：(value, type)
2.接口值保存特定底层具体类型的值。
3.调用接口值上的方法，会在其底层类型上执行同名方法。

可以把接口值简单理解为**一个接口变量的两个具体特征，值和类型**

---
#### 值的内部表示
接口值在底层确实是一个**类型指针**和**数据指针**的组合，可以想象成：

```text
( 指向类型信息的指针 , 指向底层数据的指针 )
```
这让你能通过 `%v` 和 `%T` 窥探它里面到底装了什么，对调试和理解都非常有帮助。
 
---
#### 零值接口值
当接口变量没有赋值时，它的接口值是 `nil`，此时**类型和值都是 `nil`**。  
如果你直接调用方法会导致 panic，因为不知道执行哪个类型的方法。  
例子中的 `var i I` 一开始就是 `nil`，直到你赋值后才变成具体的接口值。

---

#### A Tour Of Go中的实例
此例源自A Tour Of Go——方法和接口——11/26——接口值
在下面的示例代码中， `*T` 和 `F` 都实现了 `M()`，所以都满足接口 `I`。
接口变量 `i` 就像一个**快递盒**，上面贴着**类型标签**（`*T` 还是 `F`），里面装着**具体的货物**（`T{"Hello"}` 或 `math.Pi` 作为 `F` 类型）。
你通过 `i.M()` 调用方法时，Go 会根据盒子里**实际货物的类型**，找到那个类型对应的 `M()` 来执行。
`%v`：打印接口底层**具体的值**。
`%T`：打印接口底层**具体的类型**。
所以你能看到接口变量 `i` 在不同时刻持有不同的类型和值。

一个接口变量可以先后持有完全不同类型的值，只要它们都实现了该接口。
方法调用是“多态”的：`i.M()` 的行为由底层类型决定，这是面向对象编程里重要的“多态”体现。
 接口值的内部表示是 `(值, 类型)`。

---

示例如下：
```go
package main

import (
	"fmt"
	"math"
)

type I interface {
	M()
}

type T struct {
	S string
}

func (t *T) M() {
	fmt.Println(t.S)
}

type F float64

func (f F) M() {
	fmt.Println(f)
}

func main() {
	var i I

	i = &T{"Hello"}
	describe(i)
	i.M()

	i = F(math.Pi)
	describe(i)
	i.M()
}

func describe(i I) {
	fmt.Printf("(%v, %T)\n", i, i)
}
```

对示例进一步解释：

**接口变量**：比如 `var i I`，`i` 是一个变量，它的类型是接口类型 `I`。

**接口值**：指接口变量**当前存储的那个 `(值, 类型)` 组合**。  
所以严格说：**接口变量持有接口值**。通常交流时大家说“这个接口的值是什么”，指的就是接口变量里装的东西。

当 `i = &T{"Hello"}`
**动态类型**：`*main.T`（注意是指针）
**动态值**：一个指向 `T{"Hello"}` 的指针，即 `&T{S: "Hello"}`
所以接口值可以描述为 `(&{Hello}, *main.T)`

当 `i = F(math.Pi)`
**动态类型**：`main.F`
**动态值**：`F(3.141592653589793)` 这个浮点数
接口值：`(3.141592653589793, main.F)`

#### 核心概念：接口值 = 动态类型 + 动态值
**静态类型**：`i` 的静态类型永远是 `I`（接口类型），永远不会变。
**动态类型**：`i` 实际引用的那个具体类型（`*T` 或 `F`），运行时可以改变。
**动态值**：实际存储的数据（`&T{"Hello"}` 或 `3.14159...`）。

调用 `i.M()` 时，Go 在运行时会根据 `i` 的**动态类型**去找对应的 `M` 方法，这就是**动态分发**。  
所以同一行 `i.M()`，因为底层类型不同，执行了完全不同的代码。

---
#### 从示例中我们可以得到：

1.**一个接口变量可以先后持有完全不同类型的值**，只要它们都实现了该接口。
2.**方法调用是“多态”的**：`i.M()` 的行为由底层类型决定，这是面向对象编程里重要的“多态”体现。
3.**接口值的内部表示是 `(值, 类型)`**，这让你能通过 `%v` 和 `%T` 窥探它里面到底装了什么，对调试和理解都非常有帮助。
